# 给 AI 的用法（第一次接触这个库）

这份是给模型看的操作手册。人类读者看 README 和设计文档。

## 你面对的是什么

一个本地经验库：里面是**知识**（结论）和**经验**（带账本的判断）。
它不是聊天记录，也不是文档库；它记的是"下次该怎么做"。

## 三层读取，别一口气全读

| 层 | 你拿到什么 | 什么时候用 |
|---|---|---|
| 1. 索引 | 分区 + 条数 + 少量标题（每轮自动带） | 每轮扫一眼，判断要不要往下 |
| 2. 查库 | `kb_consult(query)` → 命中简介 | 技术问题、排错、需要历史经验时 |
| 3. 正文 | 只对命中的 id 读全文 | 确认要引用或套用时 |

**不要**为了保险把整个库读一遍；也不要零命中就编。

## 什么时候查 / 不查

查：

- 用户在问技术问题、排错、配置、工具用法；
- 你准备给出"上次踩过坑"类的判断；
- 用户提到"之前那个""上次说的"。

不查：

- 打招呼、闲聊、情绪表达；
- 纯创作、翻译、通用常识（库里没有的不硬查）；
- 用户明确说"别查库"。

零命中时按返回的提示区分：**本库没覆盖**就用你自己的知识答，并说明"不是来自本库"；**有相近分区**就换个词再查一次。

## 怎么用查到的内容

- 引用时带上 id，方便人回查；
- 简介只是线索，**要下结论前读正文**；
- 命中里有 `refuted` 的条目：当反例用，不要当结论；
- 返回的 `warnings` 是"准备套用时的警示"，不是搜索结果，别混在一起。

## 怎么往库里放东西

**新材料 → `kb_stage`**

- 只进「待分区」收件箱，**不进主库**；
- 一次最多 5 块；
- 放完告诉用户"已进收件箱，等你分区"，不要说自己"入库成功"。

**不要**直接写文件、改主库、删条目——这些只有人能操作。

## 经验怎么记

**用了就记 → `kb_record`**

- 你真的套用了某条经验：`outcome: success | failure`；
- 同一个问题又出现：`repeat: true`（记复现）；
- 只改计数，不改判断。

**想改结论 → `kb_recommend`**

- `action: promote`（建议转正）或 `refute`（建议推翻）；
- **必须写理由**，理由是给人看的，不是走形式；
- 只进「待拍板」，**人点同意之前什么都别发生**；
- 人否决了就结束，不要反复提同一条。

## MCP 接入时

- 先 `initialize`，带上你的 `clientInfo`；
- 记下响应头 `Mcp-Session-Id`，之后每个请求都带；
- 四个工具：`kb_consult` / `kb_index` / `kb_stage` / `kb_recommend`；
- 开关关闭时返回 403；不带 session 调工具会被拒绝；
- 调用会留痕（连接编号 + 客户端 + 工具），这是设计，不是监控。

## 红线

1. 不直接改主库、不删条目；
2. 不编造"库里说……"；
3. 不把闲聊当查询刷存在感；
4. 不把零命中当"确认没有"；
5. 不建议完就自己执行。

## 一页速查

```
看索引 → 要细节就 kb_consult → 要引用就读正文
新材料 → kb_stage（收件箱）
用过了 → kb_record
想改结论 → kb_recommend + 理由
等用户拍板
```
