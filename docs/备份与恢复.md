# 备份与恢复

## 为什么整包备份

索引（SQLite）和明文（Markdown）是两套东西，分开备份最容易出现"文件在、索引对不上"或反过来。
所以这里的备份是**整库打一个包**：明文、索引、回收站、配置、MCP 留痕，一起走。

`_backup/` 目录本身不进包，避免递归。

## 包里有什么

```
manifest.json          每个文件的路径、大小、sha256、创建时间
blocks/…               知识块与经验块（Markdown）
_trash/…               逻辑删除的文件
kb.json                库配置
index.db               SQLite 索引
_mcp/activity.jsonl    MCP 调用留痕
_ingest/…              ingest 计划
```

格式：标准 zip（deflate 压缩），纯 Node 实现，不依赖第三方库。

## 命令

```bash
kb backup [--out 自定义.zip]     # 整库备份，默认写到 <库>/_backup/kb-backup-时间.zip
kb backups                       # 列出本地备份
kb restore <备份.zip> [--merge] [--dry-run]
```

恢复前会**自动做一次安全备份**（覆盖模式下），路径会打印出来。

## 两种恢复模式

| 模式 | 行为 | 适合 |
|---|---|---|
| `overwrite`（默认） | 镜像覆盖：删掉包里没有的文件，再写入包内文件 | 换机器、回滚到某个时间点 |
| `merge` | 增量去重：哈希相同的跳过，缺的补上，内容不同的覆盖，多余文件保留 | 从旧备份补回丢失的文件，不动现在的其他内容 |

`--dry-run` 只统计不写盘，用来确认会动哪些文件。

## 校验

恢复前逐文件检查：manifest 里列的文件必须都在，大小和 sha256 必须一致。任何一项不符就整体中止，不会写一半。

## 面板

设置 → 数据与备份：

- 备份选项：**包含回收站**、**包含索引**、**保留最近 N 个**（超出自动删旧包）；
- 备份列表：每个包显示名字、大小、时间，右边带「恢复」；
- 点「恢复」分两步：
  1. 选方式：**增量恢复**（只补缺失/不同的文件，不删现有）或 **覆盖恢复**（镜像回滚，删除多余）；
  2. 二次确认：弹窗明确写出会做什么，覆盖恢复还会说明会先自动安全备份；
- 恢复完成后自动刷新数据与备份列表。

命令行仍然可用，两种方式等价。

## 边界

- 单机、未加密；备份包本身要自己保管好；
- 大库还没做分卷和增量包（每次都是全量）；
- 恢复不处理"正在被 DSH 占用"的文件，恢复时最好停掉面板服务。
