# 参数与可调性

我们的默认值不是"最完美"，只是**一个能跑起来的起点**。这份文档说清楚：哪些参数可以自己调、调到什么程度、调了要不要留痕。

## 三类参数

### A. 自由调（改了立即生效，不用报备）

这些是"口味"参数，不影响权限边界。

| 参数 | 默认 | 范围/说明 | 位置 |
|---|---|---|---|
| 索引摘要显示几个分区 | 8 | 越大越占 token | `indexSummary` `topDomains` |
| 每区显示几条标题 | 2 | 同上 | `indexSummary` `titlesPerDomain` |
| 检索返回条数 | 8 | 越大越费上下文 | `kb_consult` `limit` |
| 软件日志保留天数 | 7 | 通知频率用 | 设置 `experience.notifyAfterDays` |
| 小经验区每日上限 | 5 | 免审模式用 | 设置 `experience.auto.maxPerDay` |
| 备份保留个数 | 5 | 面板设置项，0 = 不清理 | `createBackup` `keep` |
| 优先级权重 | 4√复现 + 3成功 + 2使用 + 2补充 + 5人票 | 改权重会改排序，不改准入 | `experience.mjs` `priority` |
| 转正/推翻门槛 | 成功 ≥2、复现 ≥2、边界非空 | 见《经验块规格》6.1 | `proposals.mjs` `gateWarnings` |

改这些默认值不用改架构；如果改了仓库里的默认，记一条决策日志。

### B. 收紧自由、放宽要记账

这些靠近边界，调之前想清楚。

| 参数 | 默认 | 收紧 | 放宽 |
|---|---|---|---|
| 经验模式 | 审核 | 随时 | 开免审（只进小经验区）可以，但要接受"人审变事后看" |
| `auto_refute` | 关 | 随时 | 开启后自动记反例候选，必须留审计记录 |
| `audit_required` | 开 | — | 不建议关；关了就等于放弃追溯 |
| 反例警示 | 开（R1 落地） | 随时 | — |

放宽的共同要求：**在宿主自己的外层实现**，写明、留痕、可回滚。骨架不提供这类开关，也不为外层行为背书。

### C. 不可调（骨架的边界）

- 主库写入必须由人触发；
- 推翻（refute）永远走人审，免审模式也不行；
- 反例不物理删除；
- MCP 不给主库写后门，只能到收件箱与待拍板。

**边界不开放。** 宿主想要更低延迟，只能在外面套一层自己负责的外套，不能要求骨架改语义。

这三类之外，欢迎按自己的场景调。我们的默认值只对"个人、单机、中文检索"这个场景负责，换个场景就该换参数。

## 调参之后

- 只动了 A 类：不用登记；
- 动了 B 类：在你的宿主配置里写清楚，并保证有审计；
- 改了仓库里的默认值：在《决策日志》加一条 D-xxx，写清为什么。
