# 经验块规格（v1，R0 实现）

> 依据：手稿 ⑥（各知识块中的经验块）、⑪（关联表）、⑫（块头）、⑬（写入流程），
> 加上 2026-10-31 对话里作者定的规则。
> 这是实现规格，不改动 `设计说明/` 里的作者框架。

---

## 1. 定位

**经验块不是"操作记录"，是知识库使用过程中长出来的新判断。**

| | 知识块 | 经验块 |
|---|---|---|
| 回答 | 是什么（know-that） | 该怎么办、什么时候不灵（know-how） |
| 来源 | 外部材料 | 使用中的新问题、独特认知、跨领域融合 |
| 会不会变 | 相对稳定 | 会融合、会派生、会被推翻 |
| 有没有账 | 没有 | 复现/补充/使用/成功/人票 |

案例（做过什么、成没成）不是经验块，是经验块的**证据**。

## 2. 五个动作

| 动作 | 输入 | 结果 |
|---|---|---|
| **套用** apply | 一条经验 + 本次结果 | `used+1`；成功则 `succeeded+1`；失败可收窄 `limits` |
| **自创** insight | 一个新判断 | 新经验，`kind=insight`，无融合来源 |
| **融合** merge | ≥2 条经验或知识块 | 新经验 `kind=fusion`，`fused_from=[...]`；旧块标 `superseded_by` |
| **推翻** refute | 一条经验 + 反证 | `status=refuted`，`refuted_by=[...]`；不删，当反例 |
| **跨域派生** transplant | 一条经验 + 新领域 + 试用结果 | 成功则新经验 `kind=transfer`，`scope=新领域`，`derived_from=[父]`，计数从 0 起 |

派生体保留父节点；父节点继续在原领域服役。融合产出新块，不原地改旧块。

## 3. 字段

```yaml
id: k261031uwyzfc
type: experience
kind: insight | fusion | transfer
claim: 一句话判断（可复用的方法或结论，不是"我做了什么"）
scope: 适用领域 + 适用条件
limits: 什么情况下不成立
status: candidate | verified | refuted
tier: probation | main          # 小经验区 / 主库
lineage:
  fused_from: []                # 知识块或经验块的 id
  derived_from: []              # 跨域派生的父经验
  superseded_by: ""             # 被哪条新经验替代
  refuted_by: []                # 反证
evidence: []                    # 案例、测试、对话、来源
accounting:
  used: 0
  succeeded: 0
  occurrences: 0                # 复现：同一问题又出现
  refined: 0                    # 补充：又被补充/修订
  human_vote: 0
  pinned: false
  last_seen_at: ""
  last_used_at: ""
created_at / modified_at / version / editor / source / area
```

## 4. 账与优先级

```
优先级 = 4×√复现 + 3×成功 + 2×使用 + 2×补充 + 5×人票
        + 置顶(1000)
        − 衰减
```

- 复现开方：第 9 次出现的加成是第 1 次的 3 倍，防止一个高频话题压死整页；
- 衰减从 `max(last_seen_at, last_used_at, modified_at)` 起算，闲置 30 天后每天 −0.5；
- 公式不显示给用户，只显示"为什么排前面"（复现 5 次、用过 3 次成 2 次……）。

**闸门**：复现只影响排序、通知、小经验区的展示顺序；**不能单独把 `probation` 推进 `main`**。转正要人点头，或有成功证据。

## 5. 三档模式（设置项）

| 模式 | AI 权限 | 打扰方式 |
|---|---|---|
| `review`（默认） | 只能提名 | 当场问，每轮 ≤2 条，同主题 24h 冷却 |
| `auto` | 直接写入**小经验区**，可自行融合升级 | 攒够 10 条或 7 天通知一次 |
| `off` | 不自动生成 | 只有用户手动记 |

**小经验区 = AI 的沙盒，主库 = 人的领地。**
小经验区里的条目可检索、可被套用，但标"未定"，权重低于主库；转正后进主库。

## 6. 提名与拍板

AI 的提议必须像人话：

```
我觉得这次可以长一条经验：
  「pnpm 被沙箱挡住时，把 store-dir 指到工作区就能装。」
  依据：E3 用了两次成一次；第 17 条笔记里的报错。
  范围：Windows + 沙箱。
  跟 E1 有重叠，可以合并，也可以单留。
  [要] [改一下再要] [不要]
```

| 动作 | 落盘 | 留档 |
|---|---|---|
| 要 | 生成块，`decided_by=human` | 时间、原始提议 |
| 改 | 以人改的为准，AI 原文存 `proposed_claim` | 改了什么 |
| 不要 | 不生成 | 可选理由；同主题连续拒两次 → 以后只进小经验区 |

## 7. 价值判据（不拿小东西当经验）

三条至少中两条：

1. **可复用**——换个问题还用得上；
2. **有代价**——不知道会踩坑，或错了成本高；
3. **不显然**——不是查文档第一行就能看到的常识。

## 9. 存放与归属（2026-10-31 定）

**经验出生在哪个领域，就归在哪个领域。** 领域文件夹里知识与经验并排：

```
blocks/
  数学/
    knowledge/<分片>/<id>.md
    experience/<分片>/<id>.md
  物理/
    knowledge/...
    experience/...
catalog/
  数学.md          ← 自动生成：本领域的知识清单，每条下面列它的经验
```

规则：

1. **出生地**：经验解决的是哪个领域的问题，家就在哪个领域；融合出来的经验也一样——**问题在哪，家在哪**。
2. **迁移不搬家**：在别的领域想起数学的经验，只是引用；数学那条不移动、不改路径。
3. **成功才派生**：跨域套用成功，才在目标领域的 `experience/` 下新建一条，`derived_from` 指回原经验；原经验不动。
4. **跨域检索默认全开**：检索不限当前领域（否则"突然想起"就没了），命中时标出来源领域。
5. **孤儿不连坐**：知识块删除时，经验的 `primary_knowledge` 置空、标 `orphaned`，留在领域里等重挂，不跟着删。

这套做法与 2026 年的图记忆综述（[arXiv:2602.05665](https://arxiv.org/abs/2602.05665)）一致：记忆分 knowledge / experience 两类，节点独立、关系用边表达，而不是把经验嵌进知识节点内部。

## 10. R0 做什么 / 不做什么

**做**：建块、套用、推翻、融合、跨域派生（命令或提议）、三档模式、优先级排序、小经验区、转正。
**不做**：自动识别"同一问题又出现了"（R1 语义聚类）、AI 自动发起融合（R1）、常驻推荐（R1）。

## 11. 仍未定的三条（先按默认走）

1. 经验正文放什么 → 默认 `claim` 在上，正文放依据/推导/边界；证据单独结构化；
2. 跨域"试用成功"谁判 → 默认 AI 自报，你可改；
3. 小经验区阈值 → 默认 10 条 / 7 天，可在设置里调。
