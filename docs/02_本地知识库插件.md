## 2.1 目标【原】

作者原话（04 页开头）：

> 你是否想让 AI 懂得更多？是否想让 AI 在进行如开发、程序、纠错、娱乐等场景时不用一遍遍让 AI 去理解寻找相关知识！该插件可以让 AI 主动或被动上网寻找，或自行提供材料，并让 AI 整理并固化至本地成为知识库；在对知识库的运用中还可灵活更新已有内容，AI 会自行调用知识库。

定位一句话【补】（供 README 使用，作者确认后再用）：

> 普通知识库记得住知识，记不住经验。这个插件把经验也变成条目：可检索、可引用、可验证、会过期。

## 2.2 原设计要点【原】

以下编号沿用作者手稿，**内容未经改写**。

**① 独立界面**
知识库拥有独立界面，可设置，可对内容查看、编辑、删除，可导出、导入。

**② `/知识整理` 入口**
在聊天开头输入 `/知识整理`，开启让 AI 主动获取，或根据提供材料、按后续输入的需求开始整理收录。若为上网搜集，则让 AI 多渠道、广范围比对，获取整合或更新至知识库，并更新索引。

**③ 被动整合**
正常聊天或开发场景中，若 AI 判定或上网搜索过相关知识，会向用户发起"整理知识收入知识库"的请求。可在设置中开启或关闭，也可允许 AI 自行行为。用户也可主动使用指令／提炼对话，对那些信息进行整合。

**④ 索引（三级读取）**
把知识类型划分为多个知识块，以索引及目录快速查找；知识过多时开启多级索引。**AI 不会一次读取全部知识**，而是：多级索引 → 知识简介 → 对应知识块，以减少 tokens 消耗。

**⑤ MCP 服务**
界面中可开关 MCP，开启后显示 MCP 地址（也有局域网地址）。可选每次打开 DeepSeek Harness 后自动开启。其他 AI Agent 可测试连接；测试成功返回摘要集与介绍，并请求连接者上报自身信息、领取连接编号／写入编号。其他 Agent 可通过 MCP 获得插件大部分功能（查询、编辑、删除等）。作者注：冲突问题后续再想。

**⑥ 经验块**
随着知识库的运用，会出现新问题、独特认知、跨领域知识融合等内容，可融入经验块，形成便于利用的"经验"，在解决问题时更快更好。

**⑦ 唯一标识与映射寻址**
所有内容创建时拥有各自的唯一身份标识，或用创建日期 Hash 作为自身标识。插件自带映射寻址器，通过身份标识注册，把虚拟定位（身份标识）与实际地址（文件实际地址）打通。每当知识移除或写入新知识时，排查冲突并对新内容进行映射。

**⑧ 数据收录**
任何知识都可收录整理；也可在面板手动创建，或对 AI 整理不满进行修正。用 `/调用 xx` 即可让 AI 在对话中读取 xx 知识库内容并加以利用。

**⑨ 常驻模式**
设置中可开启"常规"，让 AI 在新一轮对话中先读取知识库索引和简介再回答，用得上再读正文。

**⑩ 独立文件夹**
每个知识块区均为独立文件夹，主文件采用常用文本格式。

**⑪ 关联表**
为提供更强的知识整合使用、扩充理解、跨领域迁移，关联表可把多种强关联的不同知识串起来，也可将零散知识块串联。AI 在每次知识库活动时会主动或**邀请用户共同确定**知识关联或跨领域关联；可在设置中关闭。

**⑫ 块头信息**
每个知识块头部包含：来源整理处／网址、数据库日期、最后修改日期、创建日期、编辑版本信息（可开启回滚模式，代价是存储空间增加）。参与修改的 AI 或 MCP 渠道会分配编辑者编号与自身信息，便于清楚是谁在改。

**⑬ 写入与删除流程**
内容写入缓存区 → 发送进编辑队列 → 写入成功 → 返回成功；失败 → 返回失败。删除：发送删除请求 → 进入队列 → 删除成功 → 返回成功。其他操作同理。操作成功后全域广播：谁执行了什么操作、状态（成功/失败）、操作内容，并作为日志存入日志文件夹；日志可自动或手动清理，也记录每次运行情况。用户也可自行提供知识去整理。

**⑭ MCP 连接标识**
每个测试连接时均返回执行标识码（回收机制作者仍在考虑）。

## 2.4 写入时序【补】

作者已给流程，执行方补上"谁在什么时机介入"。

```
用户/对话
   │
   ▼
① 触发判定（AI 判定：新问题？跨域？失败？）
   │
   ├─ 低价值 ────────────────▶ 不写
   │
   ▼
② 生成候选块（未入库，标 unverified）
   │
   ├─ 有来源 & 高置信 ───────▶ 直接入库（unverified）
   │
   └─ 无来源 / 跨域融合 ─────▶ 进入共判队列
                                  │
                    ③ 共判（批量，非逐条）：确认 / 改写 / 否决
                                  │
                                  ▼
                          入库，改写过的标 human-verified
   │
   ▼
④ 去重与冲突检查（同 id / 同内容 hash）
   │
   ▼
⑤ 写入缓存区 → 编辑队列 → 落盘 → 回执
   │
   ▼
⑥ 更新索引 / 关联
   │
   ▼
⑦ 使用后回写 used / succeeded → 影响 decay
```

**规则【补】**（待作者确认）：
- 只有 `result=success` 且 `succeeded ≥ 2` 的经验，才允许被主动推荐进上下文；其余只能被搜到。
- 失败经验也存，标 `result=failure`，作为反例；反例不参与推荐，但检索时可选显示。
- `decay` 长期下降的块不删除，只沉底。
- 人类改写过的条目，权重高于 AI 自建条目。

## 2.5 模块定义【补】

每个模块独立可运行、可测试、可交付。

### KB0 存储底座
- **职责**：提供"块 → 文件夹 + 元数据"的落地存储。
- **输入**：块对象。
- **输出**：磁盘上的文件 + 一份元数据索引（推荐 SQLite）。
- **验收**：写入 100 个块，冷启动后能全部读回，顺序与内容不丢。
- **依赖**：无。
- **不做**：不做检索、不做界面。

### KB1 块与寻址
- **职责**：生成唯一 id、维护 id ↔ 文件路径映射、处理冲突与重映射。
- **输入**：新块内容。
- **输出**：id + 路径 + 映射记录。
- **验收**：删块、改块、重名块三种情况下，映射不指向错误文件。
- **❓待定**：Q8（id 方案：内容 hash / 创建时间 hash / 随机）

### KB2 收录管线
- **职责**：三个入口统一到一条管线：`/知识整理`、被动请求、手动创建/修正。
- **输入**：原始材料（对话片段 / 文件 / 网址）。
- **输出**：候选块列表（未落盘）。
- **验收**：三种入口产出的候选块结构一致。
- **不做**：本模块不决定"该不该写"，只负责产出候选。

### KB3 索引
- **职责**：一级索引（块清单 + 简介）、多级索引（分类 → 子类 → 块）。
- **输入**：块清单。
- **输出**：可被外部读取的索引文件。
- **验收**：给定一个查询词，返回 ≤N 条候选 id，不返回正文。
- **❓待定**：Q3（全文 / 语义）

### KB4 检索与按需读取
- **职责**：索引 → 简介 → 正文，三级逐步展开，控制 token。
- **输入**：查询。
- **输出**：第一层 id 列表、第二层简介、第三层正文（按需）。
- **验收**：一次问答消耗的 token 数明显低于"全量塞入"。
- **依赖**：KB3。

### KB5 经验块
- **职责**：经验条目的写入判定、记账（used/succeeded）、衰减、反例标记。
- **输入**：一次任务的结果。
- **输出**：新建或更新的经验条目。
- **验收**：连续 10 次任务后，能指出"哪条经验被用过、成了几次"。
- **❓待定**：Q4（写入判据）

### KB6 关联表
- **职责**：建立、存储、遍历块与块之间的关联；支持人机共判关联。
- **输入**：两个及以上块 id + 关系。
- **输出**：关联记录。
- **验收**：从一个块出发，两跳内能到达相关块。
- **❓待定**：Q6（关系类型）

### KB7 共判与版本
- **职责**：候选块的确认／改写／否决；版本记录；回滚。
- **输入**：共判队列。
- **输出**：裁决结果 + 版本记录。
- **验收**：任意块可回到上一版本，且被否决的块不进入检索。
- **❓待定**：Q5（共判粒度与频率）

### KB8 入口
- **职责**：面板 / 指令 / MCP，三选一先做一个。
- **验收**：作者能不看文档完成"存一条、找一条"。
- **❓待定**：Q1 Q2（形态与技术栈）

### KB9 MCP 服务
- **职责**：把查询、编辑、删除暴露给其他 Agent；连接时返回执行标识码。
- **验收**：另一个 Agent 能连上、查一条、拿到结果。
- **❓待定**：Q9（是否开放局域网）
- **⚠️安全**：作者原设计允许"其他 Agent 编辑、删除"。执行方建议默认只读，写入需显式开启。**此为冲突 C-201，待裁决。**

### KB10 广播与日志
- **职责**：操作成功后广播"谁做了什么"；写日志；日志清理策略。
- **验收**：一次写操作能产生一条可读日志。

## 2.6 实现轮次【补，不改框架】

> 原则：**每一轮结束，作者自己都要能打开它用。**
> **红线：v0 必须包含经验块与共判，否则它与普通笔记软件没有区别，项目失去存在理由。**

| 轮次 | 内容 | 交付判据 |
|---|---|---|
| **R0** | KB0 + KB1 + KB2（仅手动与 `/知识整理`）+ KB4（全文检索）+ KB5（记账，不做衰减）+ KB7（批量共判） | 存 100 条笔记；问一个问题能引出来源；能记一条经验并查到它 |
| **R1** | KB3（多级索引）+ KB6（关联表）+ `/调用` | 跨两个领域的知识能被关联起来 |
| **R2** | KB9（MCP）+ KB10（广播日志）+ 版本回滚 + 衰减 | 另一个 Agent 能用；操作可追溯 |
| **R3** | 界面完善、导入导出、参数面板 | 可以发给别人装 |

## 2.8 独特性自评

**这是三个项目里唯一有组合独创性的一个。**

- 与 ExpeL：经验提炼与复用同构；但 ExpeL 不区分"知识块 / 经验块"，也没有人机共判。
- 与 HippoRAG：关联遍历同构；但 HippoRAG 用图算法，作者的关联表是显式记录 + 人机共同确认。
- 与 Mem0：写入/更新/删除的流水线同构；但 Mem0 没有"验证状态 + 复用计数 + 衰减"这一层。

**独特点在于：把"经验"和"知识"放进同一个命名空间，用同一套寻址、索引、共判机制管理，并让人参与写入判定。**

先进性：中高（组合层面，非算法层面）。创意：高。

> 注：以上对照可查证，见《04》，不作为改动框架的理由。
