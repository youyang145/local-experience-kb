# 一致性清单（v1.0）

给别人重写这套骨架时用：凡是标"必须"的，行为对上了才算兼容；标"建议"的是体验项。

## 一、数据

- [ ] **必须** 一条知识 = 一个 Markdown 文件，开头是 YAML front matter（`id/type/title/domain/created_at` 至少这些）；
- [ ] **必须** id 不依赖文件路径，文件搬家后仍能对上；
- [ ] **必须** 索引（SQLite 或别的）可以删掉、从明文全量重建；
- [ ] **必须** 删除是逻辑删除：文件进 `_trash/`，索引里标 `deleted_at`；
- [ ] **建议** 分区两级 `分区/主题`，加上 `待分区` 收件箱。

## 二、查库

- [ ] **必须** 先判"这轮要不要查"：空查询、纯符号、闲聊不查；
- [ ] **必须** 返回索引摘要（分区 + 条数 + 少量标题），不返回全文；
- [ ] **必须** 全文检索失败时拆词兜底，不能因为生僻组合直接零命中；
- [ ] **必须** 零命中时分两种说法：有相近分区 / 本库没覆盖；
- [ ] **建议** 两字中文也能查（bigram 或等价方案）。

## 三、经验

- [ ] **必须** 经验有账：用过、成了、复现、补充、人票；
- [ ] **必须** 被推翻的经验不删，标 `refuted`，检索默认不主动推荐；
- [ ] **必须** 准备套用某条经验时，给出同主题反例警示；
- [ ] **必须** 转正、推翻只能由人拍板；AI 只能建议；
- [ ] **建议** 支持融合与跨域派生，并记录血缘。

## 四、MCP

- [ ] **必须** `initialize` 下发连接编号，记录 `clientInfo`；
- [ ] **必须** 后续请求校验 `Mcp-Session-Id`；
- [ ] **必须** 只读工具（consult/index）和写入工具（stage/recommend）分开；
- [ ] **必须** stage 只进收件箱；recommend 只进待拍板；
- [ ] **必须** 每次调用留痕：时间、编号、客户端、工具；
- [ ] **必须** 开关关闭时返回 403；
- [ ] **建议** 提供 `specVersion`，工具变更时升级。

## 五、自测方式

1. 建空库，`consult("你好")` → 不查；
2. `consult("必然不存在的词")` → 零命中 + "本库没有覆盖"；
3. 入一条知识，用报错原文里**不在标题**的词查 → 应命中；
4. 写一条经验并记两次成功 → 优先级上升；
5. 推翻它 → 检索不再推荐，但准备套用时出现警示；
6. MCP：不带 session 调 `tools/call` → 报"先 initialize"；
7. 关掉 MCP → 所有请求 403。

七条全过，算行为对齐。
