# 术语与技术说明

这份文档定义这套设计里的**词**和**不变量**。
别人引用时，按这里的词来；不按这套词，就是另一套设计。

## 一、术语

| 术语 | 英文 | 定义 |
|---|---|---|
| 知识块 | KnowledgeBlock | 可独立寻址的一条知识，一个 `.md` 文件 |
| 经验块 | ExperienceBlock | 从使用中长出来的判断，有生命周期和账本 |
| 块头 | front matter | 文件开头的元数据（id、来源、领域、类型、血缘） |
| 映射寻址器 | address mapper | 身份标识 ↔ 文件实际路径的对照，路径可重建 |
| 出生领域 | birth domain | 经验被解决时所在的领域；迁移只引用，不搬家 |
| 共判 | co-adjudication | 候选入库前的批量人工裁决：确认 / 改写 / 否决 |
| 小经验区 | probation | AI 的沙盒：免审写入、可检索、标"未定"、权重低 |
| 主库 | main | 人的领地：经人拍板或转正后才进入 |
| 套用 | apply | 用一条经验处理当前问题，记 `used`，成功再记 `succeeded` |
| 自创 | insight | 没有融合来源的新判断 |
| 融合 | fusion | 两个及以上块合成一条新经验，来源标 `superseded_by` |
| 推翻 | refute | 判定一条经验不成立，保留为反例，不删除 |
| 跨域派生 | transplant | 在另一个领域验证成功后，派生一条该领域专用的经验 |
| 复现 | occurrence | 同一个问题**又出现**，与"用过"不同 |
| 补充 | refine | 经验被追加新条件、新证据或新边界 |
| 人票 | human vote | 人对一条经验投 +1 / −1 |
| 优先级 | priority | 排序用的分数，不是真理 |
| 反例通道 | warnings | 检索响应里附带的警示，不占正文召回名额 |
| 替代 | superseded_by | 旧经验被新经验取代，旧块仍可被引用 |
| 孤儿 | orphaned | 来源知识块被删、经验仍在库中的状态 |
| 三档模式 | review / auto / off | AI 提名后的人工介入程度 |

## 二、不变量（实现必须满足）

1. **记账不用问，长经验必须问。** 套用/复现的计数是记账，直接写；生成、融合、派生、推翻是长经验，必须经过人。
2. **AI 不得自动推翻；推翻必须由人发起。** 即使开了免审，废掉一条经验的权力也不交给 AI；人自己点"推翻"不受此限。
3. **复现只影响排序与通知，不单独放行转正。** 频次不等于价值。
4. **派生不双计。** 父经验不因"派生成功"加分；子经验 `used / succeeded / occurrences / refined` 全部从 0 开始；派生动作本身不算一次成功。
5. **反例不进正文召回。** 默认不参与推荐；命中相关查询时以警示出现，且**默认只在正要套用或高度相似时提醒**，不每次搜索都弹。
6. **经验按出生领域归档；迁移是引用，不是搬家。** 父经验留在原领域继续服役。
7. **知识删除，经验不连坐。** 标 `orphaned`，留在领域里等重挂。
8. **索引可丢弃，明文是真相。** `index.db` 删掉能重建；目录是正文的派生视图，不单独存储。

## 三、怎么引用

引用这套设计时，建议只引三样：

- 五动作的名称与遗留语义（谁产生状态、谁保留指针）；
- 三条纪律（人审准入、复现不转正、推翻不自动）；
- 出生领域与跨域派生的计数规则。

这些都写在 `经验块规格.md` 与 `决策日志.md` 里，有编号可查。
