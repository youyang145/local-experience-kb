# 宿主怎么接（适配器契约）

这套骨架不绑定 DSH。任何宿主只要提供下面两个接入点之一，就能用；两个都提供最好。

## 两个接入点

### A. 常驻指令（推荐）

把一段很小的"目录 + 召回规则"放进宿主的系统提示，**每轮重建**，不参与对话压缩。

要求：

- 内容不超过 10 行：分区、条数、几条标题、怎么召回；
- 每轮重新求值（库会变）；
- 放在**受压缩保护**的层（系统提示），不要放普通消息；
- 拿不到系统提示层时，退化为 MCP 的 `initialize.instructions`。

DSH 上的实现：`systemPrompt.section({ name, order, text })`。

### B. 检索工具（必须）

给模型一个可调用的查库入口：

- 输入：`query`（可选 `limit`）；
- 输出：判定 + 索引摘要 + 命中简介 + 反例警示；
- 不返回全文，正文由调用方按 id 再取。

有 function calling 就用原生工具；没有就用 MCP。两者行为必须一致（见 `一致性清单.md`）。

## 只有 MCP 的宿主

没有系统提示钩子也能用，但模型不会"自动想起"库，需要：

1. `initialize.instructions` 里带上用法摘要（本仓库已带）；
2. 客户端把这段 instructions 放进对话上下文；
3. 工具描述写清楚"什么时候该查"。

代价：模型不会每轮自动看到索引，召回率取决于它是否调工具。

## 适配器要提供什么

| 能力 | 说明 |
|---|---|
| 库目录 | 一个本地路径，放 Markdown 块和索引 |
| 读 | 索引摘要、检索、读正文 |
| 写（受限） | 收件箱、提案；**主库写入必须由人触发** |
| 留痕 | 谁在什么时候查了什么、提了什么 |
| 开关 | 能整体关闭 MCP / 写入通道 |

## 不该做的

- 不要把库内容整本塞进系统提示；
- 不要给模型直接改主库的权限；
- 不要在压缩后假设"模型还记得索引"——靠 A 每轮重建，或靠 B 重新查；
- 不要把 MCP 默认开放到局域网。

## DSH 参考实现

- 常驻指令：`systemPrompt.section`（`local-kb:index`，order 400）；
- 工具：`kb_consult` / `kb_index` / `kb_stage` / `kb_record` / `kb_recommend`；
- MCP：`POST /mcp`，四个只读/受限工具 + 连接编号 + 留痕；
- 开关：面板 MCP 页手动启停，关闭时 403。
