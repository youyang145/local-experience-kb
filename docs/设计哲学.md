# 设计哲学

这套东西不是从"记忆系统"这个概念出发的，是从**做数学题**出发的。

## 灵感：一道题吃透之后

死磕一道难题，摸到底层是怎么变的，再做类似的题就能做出来——这是**举一反三**。
做错了，错题本记下来，下次不栽同一个坑——这是**反例**。
偶尔想出一种以前没见过的新解法——这是**新经验**。

这三件事，人类靠一个错题本和一点悟性就能做；AI 的"记忆"却大多只会存聊天记录，不会长经验。

所以问题不是"怎么记住更多"，是"怎么让记住的东西下一次真的有用"。

## 对应到设计

| 做题 | 这套库 |
|---|---|
| 摸到底层规律 | 知识块：可寻址、可复用的结论 |
| 举一反三 | 跨域派生：换个领域验证成功，派生一条该领域专用的经验，旧战绩不带过去 |
| 错题本 | 反例通道：被推翻的经验不删，标 `refuted`，准备套用时才提醒 |
| 想出没见过的解法 | 自创经验：没有融合来源的新判断 |
| 两道理路打通 | 融合：两条经验合成一条，旧的标 `superseded_by`，还能被引用 |

## 为什么叫"经验块"而不是"记忆"

记忆只回答"发生过什么"；经验要回答"下次该怎么办"。

所以经验有账本（用了几次、成了几次）、有边界（`limits`）、有生命周期（候选 → 主库 → 被推翻 → 变成警示）、有血缘（从哪来、替代了谁）。

## 人的位置

人给方向和判断：这条路对不对、这条经验算不算数。
AI 给结构和实现：字段怎么定、索引怎么建、测试怎么写。

所以写入要人拍板，AI 只能提名和递材料；被推翻的经验也由人决定，不交给 AI 自动处理。

## 一句实话

"做数学题"只是一个比喻，不是学术定义。术语以 [`术语与技术说明.md`](术语与技术说明.md) 为准；这套设计有没有效，要看用起来之后"重复犯错"有没有变少，不是看这段话说得好不好听。
